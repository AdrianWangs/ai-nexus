## 多 Agent 协作增强计划

### 1. 执行计划（ExecutionPlan）
让 LLM 生成执行计划，决定串行/并行：

```go
type ExecutionPlan struct {
    Mode  string      `json:"mode"`  // "parallel" 或 "sequential"
    Tasks []AgentTask `json:"tasks"`
}

type AgentTask struct {
    AgentName   string `json:"agent_name"`
    TaskMessage string `json:"task_message"`
    DependsOn   string `json:"depends_on,omitempty"` // 依赖的前置任务
}
```

### 2. 共享上下文（SharedContext）
在 Redis 中存储跨 Agent 共享数据：

```go
// pkg/session/shared_context.go
type SharedContext struct {
    TraceID string                 `json:"trace_id"`
    Data    map[string]interface{} `json:"data"`
}

// 方法
SetSharedData(ctx, traceID, key, value)
GetSharedData(ctx, traceID, key) 
GetAllSharedData(ctx, traceID)
```

### 4. LLM Prompt 改进
```
请分析用户请求，生成执行计划：
- 如果任务之间有依赖关系（如需要先查用户ID再查订单），使用 sequential 模式
- 如果任务相互独立，使用 parallel 模式
- 在 task_message 中可以使用 {{变量名}} 引用前置任务的结果

示例：
用户："查张三的订单"
{
  "mode": "sequential",
  "tasks": [
    {"agent_name": "user-service", "task_message": "查询用户张三的ID"},
    {"agent_name": "order-service", "task_message": "查询用户ID={{user_id}}的订单", "depends_on": "user-service"}
  ]
}
```

### 5. Redis 配置
```yaml
# orchestrator/config.yaml
session:
  store: "redis"
  ttl: 86400
  sliding: true
  redis:
    addr: "localhost:6379"
    password: ""
    db: 0
```

### 6. 执行流程
```
1. 用户请求 → LLM 生成 ExecutionPlan
2. 如果 mode=parallel: 并行调用所有 Agent
3. 如果 mode=sequential:
   a. 按顺序执行每个 task
   b. 执行完成后，提取结果中的关键数据写入 SharedContext
   c. 下一个 task 的 message 中替换 {{变量}} 为实际值
4. 汇总所有结果，生成最终回复
```
